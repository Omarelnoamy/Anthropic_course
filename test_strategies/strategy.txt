This sample exam is extremely valuable because it exposes the **actual thinking style** of the real exam writers. 

After analyzing all the questions carefully, here are the **highest-confidence patterns** that are almost certainly going to appear on your real exam.

# MOST IMPORTANT DISCOVERY

The exam is NOT testing memorization.

It is testing whether you consistently choose:

* deterministic systems
* scoped architecture
* explicit structure
* production-safe behavior
* maintainable workflows
* low false-positive designs
* correct orchestration responsibility

The exam LOVES answers that:

* reduce ambiguity
* preserve observability
* preserve reliability
* minimize unnecessary complexity
* isolate responsibilities correctly

---

# THE 12 BIGGEST EXAM PATTERNS

# 1. DETERMINISTIC > PROMPT-ONLY

## THIS IS VERY HIGH PROBABILITY FOR THE EXAM.

Whenever business-critical behavior exists:

Correct:

* hooks
* gates
* prerequisites
* forced workflows
* validation

Wrong:

* “just improve the prompt”
* “add confidence scoring”
* “use sentiment”
* “few-shot only”

---

## Example Pattern

### Wrong

“Tell the model to always verify customer identity.”

### Correct

“Block refund/order tools until verified customer ID exists.”

---

# Exam Trigger Words

If you see:

* refunds
* billing
* identity
* permissions
* escalation
* policy
* compliance

→ expect deterministic enforcement.

---

# 2. TOOL DESCRIPTIONS ARE EVERYTHING

## THIS IS VERY HIGH PROBABILITY FOR THE EXAM.

This appeared MANY times.

When tool routing is wrong:

FIRST FIX:

* improve tool descriptions

NOT:

* routing classifier
* ML model
* fine-tuning
* huge prompt

---

# The exam strongly believes:

Tool descriptions are the PRIMARY mechanism for tool selection.

---

# Correct Tool Description Includes

* purpose
* inputs
* outputs
* edge cases
* boundaries
* “use when”
* “do not use when”

---

# HUGE EXAM TRAP

If two tools overlap semantically:

BAD:

* `analyze_content`
* `analyze_document`

GOOD:

* `extract_web_results`
* `parse_uploaded_document`

---

# 3. COORDINATOR IS THE BRAIN

## THIS IS VERY HIGH PROBABILITY FOR THE EXAM.

Coordinator responsibilities:

* task decomposition
* delegation
* routing
* synthesis coordination
* error handling
* observability
* context control

Subagents:

* execute specialized work only

---

# Wrong Answers Usually:

* let subagents communicate directly
* let synthesis bypass coordinator
* let agents share unrestricted tools
* let agents self-coordinate

---

# Exam Philosophy

Hub-and-spoke > peer-to-peer agents

---

# 4. SUBAGENTS DO NOT SHARE CONTEXT

## MUST MEMORIZE

Subagents:

* DO NOT inherit parent memory
* DO NOT inherit prior context
* DO NOT share state automatically

You MUST:

* explicitly pass findings
* explicitly pass metadata
* explicitly pass constraints

---

# Huge Exam Trigger

If question says:

> “subagent missed earlier findings”

Answer usually:

> “explicit context passing”

---

# 5. SCOPED TOOLS > GENERAL TOOLS

## THIS IS VERY HIGH PROBABILITY FOR THE EXAM.

The exam HATES:

* giant generic tools
* unrestricted agents
* overpowered tools

---

# Example

BAD:

```txt
fetch_url
```

GOOD:

```txt
load_document
```

Because:

* constrained
* validated
* predictable
* prevents misuse

---

# Exam Rule

Restrict capability at the interface level.

NOT:

* “tell the model not to misuse the tool”

---

# 6. STRUCTURED ERRORS ARE CRITICAL

## MUST MEMORIZE

Every good error answer includes:

* failure type
* retryability
* partial results
* attempted actions
* alternatives

---

# Correct Error Pattern

```json
{
  "errorCategory": "transient",
  "isRetryable": true,
  "partialResults": [],
  "message": "Timeout while querying patent DB"
}
```

---

# Biggest Trap

The exam HATES:

* generic “operation failed”
* hiding errors
* empty success results
* terminating whole workflow

---

# 7. “LOST IN THE MIDDLE” APPEARS A LOT

## THIS IS VERY HIGH PROBABILITY FOR THE EXAM.

When middle findings are ignored:

Correct:

* key summary at beginning
* section headers
* structured outputs
* trimmed context

Wrong:

* bigger model
* larger context window
* random ordering

---

# The exam strongly believes:

Structure beats brute force context size.

---

# 8. FEW-SHOT EXAMPLES > BETTER INSTRUCTIONS

## THIS IS VERY HIGH PROBABILITY FOR THE EXAM.

If output consistency is bad:

Correct:

* 2–4 targeted examples

Wrong:

* more prose instructions

---

# Especially Important For

* review format
* extraction format
* escalation decisions
* ambiguous routing
* actionable feedback

---

# Exam Pattern

If the prompt “still behaves inconsistently”:
→ few-shot is usually the answer.

---

# 9. PLAN MODE IS FOR ARCHITECTURE

## MUST MEMORIZE

If:

* multi-file
* architecture
* multiple valid approaches
* migrations
* restructuring

→ PLAN MODE

---

# Direct Execution

Only for:

* scoped fixes
* obvious bugs
* simple changes

---

# Exam Trap

They often tempt you with:

> “start implementing incrementally”

Usually wrong for architecture.

---

# 10. BATCH API QUESTIONS ARE EASY POINTS

## VERY HIGH PROBABILITY

Memorize this table:

| Workflow           | API         |
| ------------------ | ----------- |
| Blocking PR review | synchronous |
| Overnight report   | batch       |
| Weekly audit       | batch       |
| Nightly generation | batch       |

---

# Must memorize

Batch API:

* 50% cheaper
* asynchronous
* polling
* up to 24h
* no latency SLA
* bad for blocking workflows
* no multi-turn tool calling

---

# HUGE TRAP

Questions involving:

* iterative tool use
* multi-turn loops

→ batch API usually WRONG.

---

# 11. CLAUDE CODE CONFIGURATION QUESTIONS ARE GUARANTEED

## MUST MEMORIZE

| Item                       | Location              |
| -------------------------- | --------------------- |
| Shared slash commands      | `.claude/commands/`   |
| Personal commands          | `~/.claude/commands/` |
| Shared MCP                 | `.mcp.json`           |
| Personal MCP               | `~/.claude.json`      |
| Always-loaded instructions | `CLAUDE.md`           |
| On-demand workflows        | Skills                |
| Conditional file rules     | `.claude/rules/`      |

---

# SUPER IMPORTANT

## `context: fork`

This appeared repeatedly.

Use it when:

* verbose analysis
* brainstorming
* exploration
* discovery
* codebase scanning

Purpose:

* prevent context pollution

---

# 12. THE EXAM HATES OVER-ENGINEERING

## THIS IS THE SINGLE MOST IMPORTANT META-PATTERN

The correct answer is usually:

* simplest production-safe fix
* highest leverage fix
* lowest complexity fix

---

# Examples

Wrong:

* separate ML classifier
* external orchestration layer
* huge infrastructure
* speculative caching
* complex ranking systems

Correct:

* improve tool descriptions
* add few-shot examples
* scoped tool
* prerequisite gate
* path-specific rules
* structured error metadata

When answering:

Ask yourself:

## “What would Anthropic consider the safest, clearest, most maintainable production design?”

That is usually the answer.

NOT:

* smartest
* fanciest
* most advanced
* most AI-heavy

The exam prefers:

* clarity
* reliability
* explicitness
* observability
* maintainability
* controlled autonomy
